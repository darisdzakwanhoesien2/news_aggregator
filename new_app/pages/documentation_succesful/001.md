# MCQ LLM Verification & Scoring — Documentation

## Overview
This Streamlit app verifies multiple-choice (MCQ) answers against OCR-extracted documents using an LLM (OpenRouter-compatible). It scores answers by combining the selected choice value and the LLM verification status to produce per-question and pillar-level ESG scores.

Main file: `new_app/pages/10_v2_mcq_llm_verification.py`

## Features
- Auto-detects OCR bundles for a selected company or allows manual selection of OCR bundles.
- Builds a verification prompt combining OCR text and MCQ answers and sends it to an LLM.
- Parses LLM JSON verification results and falls back to safe defaults when parsing fails.
- Computes per-question and aggregated pillar scores with configurable multipliers.
- UI with step-by-step flow, detailed question display, raw LLM reply view and downloads (JSON/CSV).
- OCR post-processing utilities to create/clean page markdown from `ocr_result.json`.

## UI Walkthrough
1. Step 1 — Select Company & Answer File
   - Pick a company folder from `data/`.
   - Select an MCQ answer JSON. The app displays metadata and loads answers.

2. Step 2 — OCR Document Text
   - The app auto-detects OCR bundles for the company or you can manually select one or more OCR bundles from the dataset.
   - Preview first 3k characters of aggregated OCR text.

3. Step 3 — LLM Verification
   - Enter OpenRouter API Key in the sidebar to enable model loading and run verification.
   - Click "Run LLM Verification" to send MCQ + OCR to LLM.
   - The app attempts to parse the LLM reply as a JSON array matching the verification schema. If parsing fails, it saves the raw reply and marks questions as NOT_FOUND.

4. Step 4 — Results
   - Overall score and pillar-level summaries.
   - Question detail tab (expandable), Score table (dataframe), Raw LLM reply, Download (JSON/CSV).
   - OCR Post-processing utilities to write/clean `pages/*.md` from `ocr_result.json`.

## Verification JSON schema (expected from LLM)
Each item in the returned array corresponds to one question:
- id (string)
- verification_status (one of: SUPPORTED, PARTIALLY_SUPPORTED, NOT_FOUND, CONTRADICTED)
- confidence (0-100)
- evidence_quote (<=250 chars) or ""
- evidence_page (string) or ""
- reasoning (string)
- suggested_answer (one of "A","B","C","D" or null)

The app enforces conservative defaults if the LLM response cannot be parsed.

## Core scoring rules
- Choice points: A=3, B=2, C=1, D=0
- STATUS_MULTIPLIER: SUPPORTED=1.0, PARTIALLY_SUPPORTED=0.7, NOT_FOUND=0.5, CONTRADICTED=0.0
- Final Score = raw_choice_points * status_multiplier

## Important functions (quick reference)
- get_ocr_text(company_dir) -> (text, source_path): discover and collect OCR text.
- collect_ocr_text(source_dir, company_base=None) -> str: load pages or ocr_result.json and returns cleaned markdown text.
- build_verification_prompt(answers, ocr_text, max_ocr_chars) -> str: assemble LLM prompt.
- call_openrouter(messages, model, api_key, temperature, max_tokens) -> str: send chat request and return assistant content or error string.
- parse_verification_json(raw) -> list[dict] | None: robust JSON extraction (supports fenced blocks).
- compute_scores(answers, verifications) -> pd.DataFrame: produce the final scoring table.

## Troubleshooting
- LLM errors / Missing API key:
  - Ensure OPENROUTER_API_KEY is set in the sidebar or .env.
  - Check network access and OpenRouter endpoint configuration.
- No OCR text found:
  - Verify `data/<company>/ocr/ocr_result.json` or `pages/*.md` exist.
  - Use the multiselect to pick OCR bundles from other folders as a fallback.
- Parsing failures:
  - The raw LLM reply is saved to help debugging. Inspect the "Raw LLM Reply" tab.
  - Ensure the system prompt in `VERIFICATION_SYSTEM_PROMPT` is not inadvertently overridden.

## Security & Privacy
- API keys are kept in session state and/or `.env`. Do not commit keys to version control.
- OCR and answer datasets may contain sensitive information — handle outputs and saved verification JSON accordingly.

## Extensibility notes
- Model discovery supports OpenRouter models; `fetch_models` returns fallback models when API key absent or fetch fails.
- Prompt truncation/selection uses simple token overlap heuristics (chunking + retrieval); this can be replaced with vector retrieval if required.
- `clean_markdown`, `write_pages_from_ocr_json`, and `clean_pages_folder` are utilities for normalizing OCR output.
